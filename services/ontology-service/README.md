# Ontology Service

`ontology-service` is the Go backend shell for Cubicle's ontology graph. The
service owns the local GraphQL endpoint, SQLite storage foundation, and typed
Ent schema that will power Cubicle's execution context.

```text
Cubicle client
 |
 v
Gin localhost server
 |
 +-- GET /healthz
 |     -> process health for local validation
 |
 +-- POST /graphql
 |     -> gqlgen now, entgql-backed ontology API next
 |
 +-- GET /playground
       -> local GraphQL playground
 |
 v
Ent typed ontology
 |
 +-- core objects
 +-- WorkSurface / WorkPane cardinality-control nodes
 +-- Through edge schemas with evidence/rank/freshness metadata
```

## Current Scope

The ontology service now has a generated Ent schema for Cubicle's first bounded
work graph. The current GraphQL endpoint still exposes the minimal health query;
the next slice wires entgql-generated object queries, filters, and mutations.

```text
included now
 |
 +-- Gin routing, recovery, logging
 +-- gqlgen schema/codegen wiring
 +-- minimal health query
 +-- SQLite storage foundation from the previous PR
 +-- HOCON/env/flag runtime configuration
 +-- Ent codegen and typed schema for the cardinality-safe ontology

deferred
 |
 +-- entgql public ontology query/mutation wiring
 +-- crawler ingestion API
```

The important direction is that GraphQL is the product query contract. REST is
kept only for health and server mechanics.

- Go `1.25.1`
- CGO enabled for `github.com/mattn/go-sqlite3`
- macOS or Linux shell

Check your local toolchain:

```bash
go version
go env CGO_ENABLED
```

Expected shape:

```text

1
```

## Setup

From the Cubicle repo root:

```bash
cd services/ontology-service
go mod download
go generate ./ent
go generate ./graph
go test ./...
```

Framework dependencies in this slice:

```text
Gin     -> server shell: routing, recovery, request logging
gqlgen  -> GraphQL schema, generated execution code, typed resolvers
Ent     -> typed schema, SQL migration metadata, generated query builders
entgql  -> GraphQL annotations for the next generated ontology API slice
SQLite  -> local persistence foundation for later ontology storage
HOCON   -> local runtime configuration files
```

## Configure

The service loads configuration in this order:

```text
defaults < HOCON config file < environment variables < command-line flags
```

Example config:

```bash
mkdir -p .data
cp config/ontology-service.conf.example .data/ontology-service.conf
```

Important keys:

```hocon
server {
  listen_addr = "127.0.0.1:48080"
  allow_public_bind = false
}

storage {
  data_root = ".data"
  database_path = ".data/graph.db"
  sqlite_busy_timeout = 5s
}

graphql {
  playground_enabled = true
}
```

Equivalent environment variables:

```text
CUBICLE_ONTOLOGY_CONFIG_PATH
CUBICLE_ONTOLOGY_LISTEN_ADDR
CUBICLE_ONTOLOGY_ALLOW_PUBLIC_BIND
CUBICLE_ONTOLOGY_DATA_ROOT
CUBICLE_ONTOLOGY_DATABASE_PATH
CUBICLE_ONTOLOGY_SQLITE_BUSY_TIMEOUT
CUBICLE_ONTOLOGY_GRAPHQL_PLAYGROUND_ENABLED
```

## Run Server

```bash
cd services/ontology-service
go run ./cmd/ontology-service serve \
  --config .data/ontology-service.conf \
  --listen 127.0.0.1:48080
```

In another terminal:

```bash
curl -s http://127.0.0.1:48080/healthz

curl -s -X POST http://127.0.0.1:48080/graphql \
  -H 'Content-Type: application/json' \
  -d '{"query":"query { health { ok service } }"}'
```

Expected responses:

```json
{"ok":true,"service":"ontology-service"}
```

```json
{"data":{"health":{"ok":true,"service":"ontology-service"}}}
```

The local playground is available at:

```text
http://127.0.0.1:48080/playground
```

Set `graphql.playground_enabled = false` or pass
`--graphql-playground=false` when you want only `/healthz` and `/graphql`.

## Design Rules

- GraphQL is the product API contract from Day 0.
- Keep REST limited to health and local server mechanics.
- Do not introduce generic durable `Object` / `Association` Ent tables.
- Model Cubicle graph concepts as typed Ent schemas and typed Through edge
  schemas.
- Avoid direct high-cardinality `Person -> everything` edges. Use
  `Person -> WorkSurface -> WorkPane -> typed Pane*Link -> target`.
- Treat surface, pane, target, relation, and endpoint identity as create-time
  facts. Ent update builders should not be able to retarget these rows.
- Register `internal/ontologyhooks.Register(client)` on every generated Ent
  client used for ontology writes so cross-row pane invariants are enforced.
- Keep generated code committed because gqlgen generation is part of the build.

## Ontology Shape

The schema intentionally uses 18 tables:

```text
core objects
 |
 +-- persons, workstreams, tickets, pull_requests
 +-- documents, document_fragments, messages, evidences

bounded person graph
 |
 +-- work_surfaces
 +-- work_panes

Through edge schemas
 |
 +-- workstream_tickets
 +-- ticket_pull_requests
 +-- ticket_document_fragments
 +-- ticket_messages
 +-- pane_document_links
 +-- pane_pull_request_links
 +-- pane_ticket_links
 +-- pane_message_links
```

Person-centered traversal is bounded before it reaches high-cardinality target
rows:

```text
Person
 |
 +-- WorkSurface(kind: documents)
       |
       +-- WorkPane(kind: documents_commented_on, target_kind: document)
             |
             +-- PaneDocumentLink
                   |
                   +-- Document
```

`WorkPane` is generic at the ontology-pattern level, but Ent edges are concrete:

```text
WorkPane
 |
 +-- documents      -> Document       through PaneDocumentLink
 +-- pull_requests  -> PullRequest    through PanePullRequestLink
 +-- tickets        -> Ticket         through PaneTicketLink
 +-- messages       -> Message        through PaneMessageLink
```

The pane vocabulary is centralized in `internal/ontology`. For example,
`documents_created` implies:

```text
surface_kind = documents
target_kind  = document
relation     = created
```

Same-row invariants are handled by Ent schema enums and immutable fields.
Cross-row invariants are handled by generated-client hooks:

```text
WorkPane create
 |
 +-- load parent WorkSurface
 +-- reject pane_kind whose implied surface does not match
 +-- reject pane_kind whose implied target_kind does not match

Pane*Link create
 |
 +-- load parent WorkPane
 +-- reject link table target that does not match pane target_kind
 +-- reject relation_kind that does not match pane_kind
```
